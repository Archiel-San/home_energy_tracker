# AGENTS.md — Guidance for automated coding/operational agents

**Purpose:** Give AI agents the minimal, actionable knowledge to build, run, inspect, and troubleshoot the Home Energy Tracker microservices.

## Quick plan for agents

1. Bring up infra (PostgreSQL, Kafka, InfluxDB, Mailpit, Kafka UI, Ollama)
2. Build or run a single service locally
3. Exercise the ingestion → usage → alert pipeline and verify side-effects

## Quick start (infra)

- From repo root: `docker compose up -d` (uses `docker-compose.yml`)
- Stop: `docker compose down`
- If DB issues occur: remove/recreate volumes or re-run `docker/postgres/init.sql`

## Build / run a service

- **Build:** `cd <service> && ./mvnw clean package` (each microservice has its own Maven wrapper)
- **Run:** `java -jar target/<artifact>.jar` or `./mvnw spring-boot:run`
- **Java version:** JDK 21 (required, declared in each module POM)

## Architecture & key components

**Microservices (top-level directories):**
- `api-gateway` — HTTP routing, rate limiting, circuit breakers
- `user-service` — Identity, auth, user preferences
- `device-service` — Smart meter registry and metadata
- `ingestion-service` — Energy data intake (REST endpoint → Kafka)
- `usage-service` — Time-series aggregation (Kafka consumer → InfluxDB)
- `alert-service` — Threshold monitoring and email alerts (Kafka consumer → SMTP)
- `insight-service` — AI-powered analysis (scheduled jobs + Ollama LLM)

**Tech Stack:**
- **Spring Boot 4.1.x** (Java 21) for most services
- **Spring Boot 3.5** (Java 21) for `insight-service` with **Spring AI** (Ollama integration)
- **Spring Cloud 2025.1.3** on gateway (Gateway Server WebMVC, Resilience4j circuit breakers)
- **No Spring Cloud Config Server** — config is per-service in `application.properties`

**Infrastructure files:**
- `docker-compose.yml` — Full stack definition
- `docker/postgres/init.sql` — Database initialization
- `docker/kafka_data/` — Kafka persistence
- `influxdb_data/` — Time-series data persistence

## Critical integration points & dataflows (explicit)

### Ingestion → Kafka → Usage → InfluxDB

**Topic: `energy-readings`**
- **Producer:** `ingestion-service/src/main/java/com/leetjourney/ingestion_service/service/IngestionService.java`
- **Consumer:** `usage-service/src/main/java/com/leetjourney/usage_service/service/UsageService.java`
- **Event format:** `{ deviceId, timestamp, watts, userId }`

### Usage → InfluxDB writes & Kafka alerts

**InfluxDB Integration:**
- Config: `usage-service/src/main/java/com/leetjourney/usage_service/config/InfluxDBConfig.java`
- Writes: `UsageService.java` batches hourly/daily aggregations
- Bucket: `usage-bucket` (see `docker-compose.yml` env vars)
- Token: Generated by InfluxDB on first startup; check logs or Compose file

**Topic: `usage-metrics`**
- **Producer:** `usage-service` (after InfluxDB writes succeed)
- **Consumer:** `alert-service` (threshold checks) + `insight-service` (optional, for analysis)

### Alert → SMTP

**Topic: `energy-alerts`**
- **Producer:** `alert-service/src/main/java/com/leetjourney/alert_service/service/AlertService.java`
- **Action:** Sends email via Mailpit SMTP (`localhost:1025`)
- Threshold logic: Compare usage against user-defined limits (daily/monthly caps)

### Insight → Ollama LLM → PostgreSQL storage

**InfluxDB + Ollama integration:**
- Service: `insight-service/src/main/java/com/leetjourney/insight_service/service/InsightService.java`
- Trigger: Scheduled jobs (configurable cron, typically daily)
- Query metrics from InfluxDB → Send to Ollama → Store recommendations in PostgreSQL
- Ollama endpoint: `http://localhost:11434` (default; set via `OLLAMA_URL` env var)

### Database (PostgreSQL)

- **Database name:** `home_energy_tracker`
- **Init script:** `docker/postgres/init.sql` (creates tables and schemas)
- **JDBC URLs in services:** Check each service's `src/main/resources/application.properties` for `spring.datasource.url`

## API Gateway (routing & security)

- **Gateway port:** `9000`
- **Routing prefix:** `/api/v1/...` proxies to localhost backends
- **Circuit breakers:** Resilience4j configured; see `api-gateway/src/main/java/com/leetjourney/api_gateway/route/*.java`
- **Security:** OAuth2 Resource Server (JWT from Keycloak)

**Excluded endpoints (no JWT required):**
- Check `api-gateway/src/main/resources/application.properties` for `security.excluded.urls`
- Typically: actuator, swagger, api-docs, health
- **`/api/v1/ingestion/**` is NOT excluded** — calls through gateway require Bearer token

**Direct service access (bypass gateway):**
- `ingestion-service` on port `8082` has **no Spring Security** — safe for unauthenticated pipeline tests
- Example: `POST http://localhost:8082/api/v1/ingestion` (no JWT needed)

## Example agent actions (curl + validation)

### Post a test energy reading (direct to ingestion, no JWT)

```bash
curl -X POST http://localhost:8082/api/v1/ingestion \
  -H 'Content-Type: application/json' \
  -d '{
    "deviceId": "dev-1",
    "timestamp": "2026-01-01T12:00:00Z",
    "watts": 1200,
    "userId": "user-1"
  }'
```

### Through the API Gateway (requires JWT)

```bash
curl -X POST http://localhost:9000/api/v1/ingestion \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer <token>" \
  -d '{...same payload...}'
```

### Verify usage-service consumed and aggregated

1. Check service logs: `docker compose logs usage-service | tail -50`
2. Query InfluxDB bucket via HTTP API:
   ```bash
   curl -s "http://localhost:8072/api/v2/query?org=MyOrg" \
     -H "Authorization: Token <token>" \
     -d "from(bucket:\"usage-bucket\") |> range(start: -1h)" | jq .
   ```
3. Check scheduled aggregation: look for "Aggregating hourly metrics" in logs

### Verify alert-service sent email

1. Check Mailpit web UI: http://localhost:8025
2. Or query Mailpit API: `curl http://localhost:8025/api/v1/messages`

### Verify Kafka topic flow

```bash
# List topics
docker compose exec kafka kafka-topics.sh --list --bootstrap-server localhost:9092

# Consume messages from energy-readings
docker compose exec kafka kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic energy-readings \
  --from-beginning
```

## Agent runbook checks (short validation)

- **Port connectivity:** PostgreSQL (5432), Kafka (9094), InfluxDB (8072), Mailpit (8025), Kafka UI (8070), Ollama (11434)
- **Kafka topics exist:** `energy-readings`, `usage-metrics`, `energy-alerts` (check Kafka UI or CLI)
- **Kafka message flow:** Produce to `energy-readings` and confirm consumption in `usage-service` logs
- **InfluxDB writes:** Query the `usage-bucket` for recent data points
- **Email delivery:** Check Mailpit UI for outgoing emails from `alert-service`
- **Service logs:** `docker compose logs <service>` or run JAR locally and capture stdout

## Project-specific conventions

- **Maven wrapper:** Present in each service; prefer `./mvnw` over system Maven
- **Package names:** Use underscores (e.g., `com.leetjourney.ingestion_service`)
- **Kafka bootstrap (host-based runs):** Use `localhost:9094` (external advertised listener in Docker Compose)
- **Kafka consumer JSON mapping:** Check each service's `application.properties` for `spring.kafka.consumer.properties.spring.json.type.mapping`
- **Ollama model:** Default is `llama2`; override via `OLLAMA_MODEL` env var

## Files to reference when automating

**Infrastructure & configuration:**
- `docker-compose.yml` — Full stack definition with ports, env vars, volumes

- `insight-service/src/main/java/com/leetjourney/insight_service/service/InsightService.java` — Ollama LLM integration

- `<service>/src/main/resources/application.properties` — Spring Boot config (ports, Kafka bootstrap, DB URL, etc.)

## Common troubleshooting

| Issue | Check |
|-------|-------|
| Services can't reach Kafka | Use `localhost:9094` (external listener) for host-based runs; `kafka:29092` for Docker network |
| InfluxDB connection fails | Verify bucket and token match `docker-compose.yml` env vars; check `InfluxDBConfig.java` |
| Emails not appearing in Mailpit | Confirm SMTP URL in `alert-service` properties is `localhost:1025`; check service logs for send errors |
| JWT validation fails at gateway | Verify token is from Keycloak and includes required scopes; check `SecurityConfig.java` |
| Ollama LLM not responding | Confirm `insight-service` can reach `http://localhost:11434`; check if Ollama container is running |
| Prometheus metrics missing | Ensure microservices are running on **host** (not Docker) with actuator metrics enabled; check `docker/prometheus/prometheus.yml` scrape targets |
